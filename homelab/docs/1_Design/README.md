## Documents Setup & Scope

**Scope of specific category documents like network, hypervisor, etc.: design only — no specific hardware or software.** These documents deliberately name **no products, brands, or tools**. Every concrete choice — which device, which operating system, which platform, which tooling — is centralized in two dedicated documents: [Design: Hardware & Prerequisites](1_Design_Hardware_Prerequisites.md) for every physical device, and [Design: Software & Prerequisites](2_Design_Software_Prerequisites.md) for every tool and platform. Those documents and this one are directly connected but answer different questions: **these documents are the *design* (the structure, the boundaries, the policies, and the reasoning behind them), the other two are the *implementation* (the actual hardware and software that realise it).** The reason for that split is that the design is the stable part and the tooling is the volatile part. The reasoning in each category document (e.g. network, hypervisor, etc.) stays true regardless of which product or tool is ultimately used to implement it. Keeping product names out of those documents means it does not need rewriting when a tool is replaced, and keeping every product name in one place means a tool swap is a one-file change. Low-level, tool-specific configuration (syntax, settings, parameters, automation roles) belongs in the [implementation/setup documents](../2_Setup/README.md) and repositories for those tools, not here.
