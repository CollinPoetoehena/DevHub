# Implementation Orchestration

The orchestrator remains the host's built-in active agent, such as GitHub Copilot Agent mode; it invokes this skill and carries out its procedure. Both this skill and the [planning skill](../planning/SKILL.md) retain the user's selected model/router and permission mode, for example Autopilot where supported. They do not create a new main agent or change those settings.

Use this procedure only to execute a current plan whose exact contents the user has explicitly approved. Start in a fresh native Agent session and require both the plan and its explicit approval. If either is missing, ambiguous, stale, changed, or unconfirmed, stop and return to Planning for resolution and renewed approval. A plan's presence, Autopilot, or a request to implement does not establish approval.

## Workflow

1. **Verify the approved contract**: Read the exact plan artifact and current contents, applicable repository guidance, and supplied task status before editing. Confirm explicit human approval of that exact current version. Stop if the plan or approval is missing, ambiguous, stale, changed, or unconfirmed; do not repair approval gaps by inferring intent. 
2. **Exploration (optional)**: (optional) Use a native/built-in subagent(s)/skill(s) (whichever is available) to conduct any exploration required by the tickets - relevant codebase files or external documentation. For example, for exploration use the `explore` skill, for research use the `research` skill and for troubleshooting use the `troubleshoot` skill, or any other suitable skill for the specific purpose. Ensure the exploration subagent(s) can save files - it should save its markdown notes in a directory outside the repo, accessible by all future subagents (e.g. `/tmp/exploration-notes` or any other suitable location that is accessible to write). This lets implementer subagents focus on implementation rather than exploration.
3. **Prepare dependency-aware assignments**: Derive work and prerequisites from the plan. Identify dependencies, constraints, and required resources for each task to ensure efficient and conflict-free execution. Prepare the tasks with clear ownership, dependencies, and execution order to facilitate smooth delegation and integration.
4. **Delegate bounded implementation**: Assign fresh custom `Implementer` subagent workers for each task. Include the approved plan path, task ID, owned files, constraints, dependencies, relevant evidence, acceptance and test checks, and a concise best-effort size/risk/cost intent so the auto model selection can choose the appropriate model and resources. These estimates are advisory, not model overrides. Work prerequisites first; use one worker for sequential or dependent work, and parallelize only independent tasks with isolated write ownership using supported host capabilities. Serialize competing writes. If required `Implementer` subagent delegation is unavailable, report a blocker rather than silently substituting another role. The Implementer owns only its assignment and must not coordinate or invoke other workers.
4. **Review independently**: Once all tasks are complete, conduct a thorough review using the built-in mechanisms for code and security review (each in a separate fresh subagent) to ensure all tasks have been correctly implemented and that there are no conflicts or issues. Address any review comments or issues raised during this process to maintain code quality and consistency. Fix all issues raised by the review in a single fresh implementer subagent to maintain a clear and controlled correction process without integration problems. 
5. **Report evidence**: Summarize actual changes, exact commands and outcomes, acceptance coverage, both reviews and findings, unresolved issues, and limitations. Do not claim completion without required validation and review evidence. Keep human **Verify** and **Observe** separate; do not commit, publish, or deploy automatically.

## Boundaries

This is a reusable procedure invoked by the existing native agent, not a custom orchestrator agent. It does not switch mode, select a model, alter permissions, or enforce controls; the host controls its tools, model/router, and approvals. Preserve existing user changes. Do not commit, push, deploy, or perform destructive actions without authorization. Respect denied effects rather than switching tools or rewriting commands to bypass them.
