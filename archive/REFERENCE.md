# Retired Reference Library

DevHub's former `reference/` folder was a personal knowledge base covering software engineering, tools, infrastructure, networking, security, soft skills, command cheatsheets, and much more; basically I tried to create a complete software-engineering encyclopedia. It is retired and removed from the working tree. This page records the decision, not a copy of the library; Git history preserves the files.

The attempt to build a software-engineering encyclopedia created an open-ended obligation to record everything I learned. Every explanation and command added another accuracy and maintenance burden, without a useful stopping point. Understanding in my head and being able to apply that understanding matter more than maintaining an exhaustive written record. Learning something does not create an obligation to document it. 

The former command collection is replaced by [simple, concise cheat sheets](../docs/cheatsheets/README.md) for selected useful commands. They save repeated lookups without recreating the reference library: no concept chapters, exhaustive option lists, or completeness goal. Official documentation, Linux man pages, and command help remain the sources for details. AI can help locate or explain information; authoritative documentation and actual behavior remain the checks on its answers.

Active project documentation links to official sources where general background is needed and records only the brief project-specific setup, decisions, constraints, or exceptions readers need. If a source disappears, I can find a current replacement rather than preserve a local encyclopedia.

The time is better spent applying knowledge, including building and operating the homelab, than collecting it for its own sake.

**Main takeaway for myself:** Information and knowledge are readily available when needed, through official documentation, tutorials, community resources, AI-assisted search, or, where something is worth keeping personally, a personal document store like OneDrive for example. There is little value in duplicating all of that information here simply for the sake of having recorded it. The more important thing to retain is the understanding developed by working with that information in practice: questioning it, determining whether it is accurate and relevant, understanding the context and trade-offs involved, and learning when and how to apply it (e.g. applying it in personal projects, work, etc.; not documenting it here in this DevHub repo or in a local encyclopedia like the retired reference explained here). Over time, those experiences build judgement. That judgement cannot be replaced by an exhaustive collection of theory or commands; it comes from using knowledge, seeing the consequences of decisions, learning from mistakes and successes, and carrying those lessons into the next problem. The goal is therefore not to remember or document everything, but to know how to find reliable information, think critically about it, connect it to existing experience, and use it to make sound decisions.
